### Task R1-1: Remove the Banner generator

The owner is deleting the Synergy Spotlight banner generator. This task removes it completely and keeps every gate green. README §0 lists only part of the work. The full list below comes from `git grep -il banner -- . ':!upstream' ':!docs/redesign' ':!docs/plans/R-redesign.md' ':!docs/plans/R-redesign'` (19 tracked files) plus the files those hits depend on. That grep leaves out this plan and the design handoff, which mention the banner on purpose. When this task is done, admin has **no** design-token exception.

Kept on purpose:
- The `/art/sets/` and `/brand/` forwards stay in `forwarded-paths.json` and `vercel.json` (decision R-11).
- `sharp` stays. `scripts/reveal-sync/{rehearse.mjs,convert.test.mjs,write.test.mjs}` import it.

- `src/tools/analytics/adminData.ts:11` mentions the app's `usePrecomputedSynergies` in a comment. The comment describes app code, so it is still accurate.
- `docs/plans/P2-port-tools.md` and `docs/plans/P3-pipelines.md` record how things were built. They keep their banner mentions, which is why Step 14's grep excludes `docs/plans`.

Removed from the bridge: `usePrecomputedSynergies`. Once the banner is gone, nothing in `src/` imports it. When R3 needs synergy data, it bridges `fetchCardSynergies` from the same app module (`features/synergies/hooks/usePrecomputedSynergies`).

Kept but re-pointed: the two non-banner cases in the bridge-boundary "design-token exception" block (`holds every other file to …` and `holds … to the rest of the design-token rules`). They now check an ordinary source path. They are the only test that admin source files get the app's token rules at all, so they are not new tests.

Outside this repo, so not a step here: the app's `CLAUDE.md` (about line 225) lists "banner generator" among admin's tools. Fixing that is an app-repo change, and the owner decides when. Nothing in admin's CI depends on it.
